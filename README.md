# КРОМКА — матчи и статистика РПЛ

КРОМКА — приложение для болельщиков РПЛ: календарь и матчи, таблица, составы, профили игроков и любимый клуб. Сейчас доступна веб-версия с установкой на главный экран. Планируется Android APK для RuStore; способ сборки ещё не выбран, Android-проекта и подписанного APK в репозитории пока нет.

## Подготовка к выпуску

Документы доступны независимо от загрузки спортивных данных: `/about`, `/privacy`, `/terms`, `/storage`, `/support`, `/licenses`. Владельцы и контакты указаны; параметры российского хостинга, домена и хранения журналов заполняются после их фактического выбора. Пока они не заполнены, политика помечена как редакция к выпуску, индексация закрыта.

`npm run release:check` проверяет веб-часть и документы, но не собирает APK и не подтверждает готовность к модерации. При запуске с локальной конфигурацией: `node --env-file=.env scripts/release-check.mjs`. Порядок выпуска: [RELEASE-CHECKLIST.md](RELEASE-CHECKLIST.md); карточка RuStore и проверки Android: [RUSTORE-RELEASE.md](RUSTORE-RELEASE.md); обработка обращений: [RELEASE-OPERATIONS.md](RELEASE-OPERATIONS.md).

## Запуск

Требуются Node.js 22 или новее и Python 3.9+ (только стандартная библиотека): при запуске Node автоматически поднимает скопированный из референса Flashscore-прокси на `127.0.0.1:8765`. Для данных, которых прокси не отдаёт, и полного резерва рекомендуется задать `GOAL_API_KEY`; резервный портретный источник необязателен:

```bash
GOAL_API_KEY="ваш_GOAL_ключ" API_FOOTBALL_API_KEY="ваш_API_Football_ключ" npm start
```

Откройте `http://localhost:4173`. Без GOAL-ключа Flashscore-прокси всё ещё может отдавать календарь, результаты и данные матча; таблица рассчитывается по завершённым играм. При отключённом/недоступном прокси без GOAL-ключа приложение показывает явно обозначенный демо-режим. Переменные в `.env.example` — только образец: сервер автоматически не читает файл `.env`.

Оба ключа используются только процессом сервера и не попадают в HTML, JavaScript или ответы API. Не коммитьте файл `.env`, не публикуйте ключи и не передавайте их браузеру.

## Что работает

- Пять основных экранов: «Сегодня» показывает игры дня и ближайший матч отслеживаемого клуба, «Матчи» — недельный календарь с фильтрами и списком тура. «Избранное» автоматически выводит предстоящие игры отслеживаемых клубов.
- Матч открывается отдельным экраном: турнирная позиция, сезонное сравнение, форма по пяти последним завершённым играм, домашне-гостевые разрезы, очные встречи сезона, составы, события и статистика. Форма и сравнения рассчитываются только по завершённым матчам; если история короче или помечена как неполная, интерфейс не дополняет её демонстрационными результатами.
- Из матча можно перейти в профиль клуба, а из ростера или состава — в профиль игрока. Профиль показывает доступные имя, номер, позицию, возраст, портрет и статистику сезона и карьеры. Отсутствующие показатели не имитируются.
- Для телефона добавлены короткие переходы между экранами, обновление с индикатором загрузки и скелетоны для запрашиваемых составов; анимации отключаются при системной настройке «уменьшить движение».
- В «Моём клубе» показаны ближайшая игра, последние пять результатов, показатели из таблицы РПЛ и домашние/гостевые результаты по завершённым матчам. Графики лиги остаются в разделе «Таблица». Демонстрационный срез помечен.
- В матч-центре отображаются все парные показатели, которые передал выбранный поставщик: исходная подпись и формат значения (например, проценты или значение с числителем/знаменателем) сохраняются, а числовая часть используется только для сравнительной полосы. Предматчевые нули не показываются как статистика; без данных поставщика экран честно сообщает об их отсутствии.
- PWA-манифест, иконка и service worker; браузерный кэш не сохраняет ответы `/api/*`.
- Календарь, результаты и матчевые сведения в первую очередь поступают из Flashscore-прокси, перенесённого из [f1dos/rpl](https://github.com/f1dos/rpl/tree/main); GOAL API дополняет отсутствующие данные и полностью подхватывает поток при сбое прокси. Турнирная таблица сначала берётся из GOAL, а при недоступности GOAL рассчитывается из завершённых матчей Flashscore. Признак полноты истории относится к первичному календарному источнику, а не к дополнительной истории GOAL.
- Клиент обновляет календарь через REST раз в 5 минут. Когда GOAL сообщает об активных играх, сервер подписывается на них одним GOAL WebSocket (до 25 матчей), сопоставляет ID GOAL с Flashscore ID и передаёт только подтверждённые обновления счёта/статуса/минуты браузеру через SSE. При потере соединения действует повторное подключение; REST остаётся резервом.
- Список игроков клуба загружается при открытии состава из Flashscore; GOAL дополняет отсутствующие сведения ростера (например, номер, возраст, позицию и фото), а при сбое прокси возвращает полный ростер.
- Если у игрока нет пригодного портрета основного ростера, сервер проверяет текущий состав соответствующего клуба через `GET /players/squads?team=…` API-Football. Резерв применяется только к портрету и только при однозначном совпадении игрока; он не заменяет имя или номер. API-Football не используется для эмблем, результатов, стартовых XI, запасных или схем.
- API-Football-кеш хранится на сервере в `.cache/api-football-squads.json`, действует 7 дней на клуб и сохраняется между перезапусками. Запрос к этому API делается по требованию — когда в основном ростере действительно не хватает портретов. Локальная защита ограничивает расход 80 API-запросами в сутки, оставляя запас от объявленного бесплатного лимита API-Football в 100/сутки. Для нескольких серверных экземпляров нужен общий кеш/лимитер; локальный файл защищает один экземпляр.
- Перед показом резервного фото сервер проверяет HTTPS/CDN-путь и содержимое. Проверенный общий серый силуэт API-Football блокируется; повторяющиеся изображения в одной группе совпадений также отбрасываются. Если картинка не прошла проверку или сопоставление ненадёжно, остаются инициалы.
- При открытии вкладки «Составы» опубликованные стартовые XI и запасные поступают из Flashscore или GOAL. Прогноз выбирает наиболее частую схему клуба по завершённым матчам сезона. Конкретные роли восстанавливаются из схем и `lineupPosition` последних 12 доступных составов сезона; центральные защитники и фланги не смешиваются. Игроки текущего ростера отбираются по минутам РПЛ с учётом совместимости ролей, без дублирования футболистов. На поле показаны роли и портреты, без минут; травмы и дисквалификации не учитываются. Если точных данных не хватает, показан список кандидатов. Если нельзя собрать полный XI, прогноз скрыт.
- События и статистика матча сначала запрашиваются у Flashscore, а при пустом ответе или ошибке — через соответствующие GOAL API endpoints. На поле игроки привязаны к порядковым позициям состава и схеме поставщика; если полный порядок не опубликован, показан список. Кольцевые диаграммы в профиле игрока и «Моём клубе» используют реальные доли с подписями значений и процентов; неизвестные значения не превращаются в нули.
- Если Flashscore-прокси недоступен, GOAL API становится полным резервом. Только если оба источника недоступны или не настроены, интерфейс показывает демо-режим; при нехватке портретов сохраняются инициалы.

События и статистика матча при открытии сначала запрашиваются у Flashscore через прокси; если ответа нет, сервер использует документированные GOAL API endpoints `/fixtures/:id/events` и `/fixtures/:id/statistics`. Для обоих источников сервер допускает только fixture ID, предварительно полученные из календаря РПЛ. GOAL-кэш событий/статистики — 1 минута для live, 10 минут для будущих и 24 часа для завершённых матчей. Если оба источника пусты или недоступны, экран показывает явное состояние без выдуманных цифр. Очные встречи и домашне-гостевые показатели считаются из завершённых fixtures первичного календарного источника. Из состава матча или клуба открывается профиль игрока с портретом и статистикой: сезонная разбивка по РПЛ и всем турнирам клуба берётся из таблицы состава, история карьеры и средняя оценка — со страницы игрока. Портреты загружаются через приложение; отсутствующие значения не подставляются.

Проверка сохранённого GOAL-ключа 11 ноября 2026 года подтвердила календарь 2026/27, таблицу из 16 клубов и доступность событий/статистики у завершённого матча. WebSocket token и handshake тоже прошли, лимит — до 25 подписок. Во время теста активной игры не было, поэтому фактическое live-изменение счёта не подтверждено; подробные результаты, квота, бесплатные альтернативы и права источников описаны в [DATA-SOURCE.md](DATA-SOURCE.md).

## Покрытие и ограничения

Сезонные endpoints API-Football не дают бесплатному плану доступ к сезону 2026/27. Поэтому интеграция не запрашивает сезонную статистику API-Football: она использует только текущий squads endpoint и только для недостающих портретов. В проверенном ответе Dynamo Moscow API-Football вернул 28 игроков; 26 изображений были портретами, а 2 — одинаковой общей серой заглушкой. Эти заглушки отфильтровываются, но фактическое число замен в каждой команде зависит от совпадения текущего API-Football игрока с ростером GOAL.

GOAL сообщает о составах для 1 357 из 1 359 матчей РПЛ в одном проверенном снимке покрытия; это не гарантия, что состав или формация будут опубликованы к каждому live-матчу. В ранее проверенном ростере Dynamo Moscow GOAL отсутствовали некоторые фото. Даже с резервным источником часть профилей может остаться с инициалами: игрока может не быть в текущем squads-ответе, имя/номер может не совпасть однозначно, CDN может быть недоступен, а типовые силуэты намеренно блокируются.

Идентификаторы 16 клубов API-Football сопоставлены с текущими ID GOAL в `server.mjs`. При смене участников РПЛ этот список нужно обновить. API-Football-кеш и дневной счётчик локальны для одного процесса/файловой системы; кластер или несколько хостов должны использовать общий надёжный storage, иначе защита от повторных запросов между хостами не действует.

## Источники и права на изображения

Основной источник календаря и матчевых сведений — прокси-метод из открытого [f1dos/rpl](https://github.com/f1dos/rpl/tree/main), а [GOAL API: покрытие РПЛ](https://goal-api.com/coverage/russia-premier-league-api) дополняет данные и остаётся полным резервом (ID лиги `cmr77dvua00a4rx061d2jre7p`). Для резервных портретов используется только [API-Football squads endpoint](https://www.api-football.com/documentation-v3). Условия, конфигурация и ограничения источников описаны в [DATA-SOURCE.md](DATA-SOURCE.md) и [MEDIA-SOURCES.md](MEDIA-SOURCES.md).

**Наличие эмблемы или фотографии в ответе любого из этих источников не передаёт проекту права на изображение или товарный знак.** GOAL и API-Football не предоставляют здесь подтверждённую лицензию на клубные эмблемы или фотографии игроков; Flashscore feed также не подтверждает лицензию на спортивные данные. Перед публичным или коммерческим выпуском получите разрешения и проверьте применимые условия поставщиков. Массовый скрейпинг сайтов клубов/лиги не используется.

В оформлении используется фотография стадиона «Крестовский ночью» — [Wikimedia Commons](https://commons.wikimedia.org/wiki/File:Krestovsky_Stadium_at_night_(cropped).jpg), автор Monoklon, [CC BY 3.0](https://creativecommons.org/licenses/by/3.0/); атрибуция указана в интерфейсе.

Подробный текущий результат проверки — 9 уникальных резервных портретов в 11 записях, 32 позиционно размеченные записи без фото и 177 неразмеченных — приведён в [PORTRAIT-COVERAGE.md](PORTRAIT-COVERAGE.md). Дубли источника не считаются отдельными подтверждёнными людьми.


## Улучшения интерфейса и избранного

- Отдельная нижняя вкладка «Избранное» показывает клубы и матчи, отмеченные пользователем. Выбор сохраняется в `localStorage` текущего браузера и не синхронизируется между устройствами.
- В «Матчах» доступны быстрые фильтры «Все», «Live» и «Избранное», а фильтр клуба покрывает весь текущий список команд. В live-режиме эти же фильтры работают поверх текущего календарного источника.
- Кнопка со звёздочкой у матча сохраняет конкретную встречу; звёздочка в профиле клуба сохраняет сам клуб. Push-уведомления не подключены.
- Создана оригинальная абстрактная эмблема «ТЕМП» без клубной символики; она используется в брендинге и установочных иконках PWA.

При просмотре продукта сверялись публичная [карточка Flashscore в Google Play](https://play.google.com/store/apps/details?id=eu.livesport.flashscoreusa_com&hl=en_US) и открытый [пример РПЛ Arena](https://github.com/f1dos/rpl/tree/main). В это приложение перенесён способ получения данных из `rpl_flashscore_proxy.py` без переделки экранов; источник остаётся неофициальным. В прежней технической проверке season-маршрут ответил 240 матчами, однако успешный ответ не подтверждает разрешение автоматизированного доступа или лицензию на повторное использование данных.


### Что взято из референсов и что сознательно не добавлено

Официальная [карточка Flashscore в Google Play](https://play.google.com/store/apps/details?id=eu.livesport.flashscoreusa_com&hl=en_US) описывает live-счёт, избранное и обновления матчей; [страница Flashscore о расширенной статистике](https://www.flashscoreusa.com/news/football-even-more-in-depth-flashscore-expands-match-statistics/6yne1Z8e/) перечисляет дополнительные игровые показатели. В ТЕМП сохранены прежние быстрые фильтры и избранное, а календарь/матч-центр используют перенесённый Flashscore-прокси. GOAL API остаётся источником дополнений и fallback; сезонные форма, очные встречи и домашне-гостевые разрезы считаются из загруженных матчей.

Открытый [RPL Arena пример](https://github.com/f1dos/rpl/tree/main) включает страницы клубов/игроков, матч-центр, избранное и сравнение. В ТЕМП сравнение расширено сводными показателями таблицы и разрезами сезона, а очные встречи строятся из завершённых fixtures. Из референса перенесён именно метод работы с Flashscore через `flashscore_proxy.py`; экраны и пользовательские сценарии ТЕМП не заменялись. Датированные JSON-снимки из репозитория не используются.
