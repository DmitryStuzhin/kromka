# Уведомления КРОМКИ

Состояние на 21.11.2026: серверные подписки и очередь реализованы, отправка и регистрация выключены. Android-проект содержит RuStore SDK 7.6.0, настройки и нативное хранение подписки. Доставка на телефон не подтверждена. Карточка приложения RuStore `2063792816` не заменяет push-проект: его ID и сервисный токен ещё нужно получить.

## Android-клиент

`RUSTORE_PROJECT_ID` передаётся при сборке Gradle (или `-PrustoreProjectId=...`), входит в BuildConfig и не является секретом. Пустое значение оставляет интерфейс настроек недоступным; фиктивный ID не используется. Сервисный токен никогда не входит в APK. Инициализирующий provider SDK удалён из merged manifest, receiver/служба доставки и provider идентификатора выключены до согласия. Инициализация выполняется в Application после явного включения пользователем, а при последующих запусках — только для включённой подписки.

Настройки доступны в Android по ссылке «Уведомления» и в «Данные на устройстве». До запроса разрешения Android проверяется доступность серверной регистрации. Для передачи токена и настроек используется нативный HTTPS-клиент с фиксированным доменом, запретом redirect, ограниченными timeout и Origin Capacitor. Случайный ID, секрет из 32 случайных байтов и токен остаются в закрытом SharedPreferences; getState возвращает только настройки и статус. Android backup выключен.

WorkManager хранит ожидающую синхронизацию и повторяет её при восстановлении сети, в том числе после закрытия процесса. Поколение настроек и последовательное исполнение сетевых запросов защищают от перезаписи свежего выбора старым запросом. При отключении показ прекращается локально сразу; DELETE повторяется до подтверждения сервера. Повторный DELETE отсутствующей записи успешен. После подтверждения удаляются ID и секрет установки. Очистка избранного также отключает доставку и удаляет нативные списки выбора.

Backend передаёт data-only сообщения. Своя Android-служба проверяет включение, системное разрешение, канал, текущий выбор и вид события; последние 100 eventId сохраняются для подавления повторов после перезапуска. При уже успешном показе с тем же tag система обновляет тот же notification. Переход использует только проверенный ID известного матча; произвольный внешний URL из push не открывается. Секреты и диагностика SDK не выводятся в logcat. Эти проверки не доказывают реальную доставку RuStore.

## Хранение и API

Node 22.13+ (на сервере Node 24) использует встроенный SQLite, WAL и транзакции. `KROMKA_PUSH_DB=/var/lib/kromka/push/push.sqlite` находится вне web-root, файлы создаются с umask 0077. В базе: случайный ID установки, SHA-256 секрета установки, push-токен RuStore, выбранные ID клубов/матчей, виды событий и дата согласия. Токены и Authorization не выводятся в журналы. Не создавать реальную регистрацию без отдельного пользовательского согласия и обновления документов клиента.

- `GET /api/push/status`: доступность регистрации и версия согласия `2026-11-21`.
- `PUT /api/push/devices/<UUIDv4>`: полная замена настроек и обновление токена. `Authorization: Bearer <случайный секрет из 32 байтов base64url>`. JSON: `{token, fixtureIds:[], teamIds:[], kinds:["goal","lineups","start","finish"], consent:"2026-11-21"}`. ID и секрет создаются клиентом один раз, хранятся только на устройстве; секрет не входит в URL.
- `GET` по тому же адресу возвращает настройки только с правильным секретом, без токена.
- `DELETE` удаляет установку и её очередь. Работает и при выключенной регистрации. Клиент должен повторять неудавшийся отзыв после восстановления сети.
- Разрешён origin только `https://localhost` (локальный origin Capacitor). Для изменения нужны правильные credentials; CORS не заменяет авторизацию. JSON ограничен 16 КиБ, списки — 100 значениями, регистрация — 10 тыс. установок; лимит API — 30 запросов в минуту на адрес. Подмена чужого UUID/токена не перезаписывает существующую установку.

Неактивные установки удаляются через 90 дней после последнего обновления, события и очередь — через 7 дней, снимки матчей — через 30 дней. Резервные копии могут содержать удалённые записи до истечения срока хранения (7 дней). API не выполняет запросов к RuStore при регистрации.

## Фоновая обработка

`push-worker.mjs` запускается отдельной службой `deploy/kromka-push.service`. Пока `KROMKA_PUSH_ENABLED=false`, он только очищает просроченные записи; запросов к поставщикам или RuStore нет. Если включён и есть установки, каждые 30 секунд запрашивает API локального приложения — открытый браузер не нужен. Обрабатываются матчи, на которые есть подписки, напрямую или через клуб.

Первое наблюдение и пауза более 5 минут создают исходный снимок без старых голов. Переход scheduled→live создаёт начало, live→finished — завершение. Рост известного счёта создаёт сообщение с текущим счётом. Снижение счёта не считается голом; повтор того же счёта, в том числе после отмены, не создаёт повторное уведомление. Один переход может объединять несколько пропущенных голов: индивидуальные авторы и минуты не выдумываются.

Составы проверяются за два часа до начала; нужны оба полных стартовых состава по 11 игроков и отсутствие признака прогноза. Сообщение создаётся один раз. Частичный или предположительный состав не считается опубликованным.

Событие и очередь получателей записываются одной транзакцией, уникальные ключи исключают повторную постановку. При изменении подписок неотправленные сообщения прежней подписки отменяются. Повторный heartbeat с теми же подписками сохраняет очередь. Удаление установки каскадно удаляет её очередь.

Доставка использует lease 60 секунд, восстановление после перезапуска, до 6 попыток с задержкой до 5 минут. TTL — 10 минут для счёта/статуса, 30 минут для составов; TTL у RuStore дополнительно ограничен 10 минутами. Ошибки временной недоступности повторяются, недействительный токен удаляется, при 401/403 отправка останавливается до исправления ключа и рестарта worker. Принятый RuStore запрос не доказывает показ на устройстве.

При обрыве соединения после приёма сообщения сервисом невозможно гарантировать единственную доставку: повтор может дойти ещё раз. Клиенту следует использовать `eventId` для подавления дублей при собственном отображении. Уже переданное провайдеру сообщение нельзя гарантированно отозвать. Периодичность проверки и задержки источников не дают гарантии мгновенного live-оповещения. Смена поставщика/ID матча может дать новый исходный снимок; исторические события не восстанавливаются.

## Включение после настройки RuStore

1. Получить push project ID, зарегистрировать package `ru.tokenapp.kromka` и SHA-256 сертификата конкретного APK.
2. Собрать APK с ID этого push-проекта и стабильной релизной подписью. Проверить SDK, разрешение Android 13+, регистрацию/ротацию токена, переход к матчу и отзыв подписки на устройстве. Сверить политику с итоговой сборкой.
3. Записать ID и сервисный токен только в `/etc/kromka/push.env` (root, 0600). Для веб-сервера и worker настроить EnvironmentFile этого файла.
4. После проверки на тестовом устройстве включить `KROMKA_PUSH_ENABLED=true`, `KROMKA_PUSH_REGISTRATION_ENABLED=true` и перезапустить обе службы. Не включать их автоматически при добавлении ключа.
5. Проверить гол, отмену/уточнение счёта, составы, старт/финиш, отсутствие дублей, перезапуск worker, потерю сети, ротацию токена, выключение уведомлений и удаление данных.

Согласованные резервные копии SQLite выполняются `node scripts/backup-push.mjs <закрытый файл назначения>`; копирование одного живого `.sqlite` без WAL не является надёжной копией. При восстановлении хранить базу вне каталога релиза и останавливать обе службы.

Документация транспорта: https://www.rustore.ru/help/sdk/push-notifications/send-push-notifications . Внешний адрес зафиксирован в коде: `https://vkpns.rustore.ru`, переадресации запрещены, проверка TLS включена.
