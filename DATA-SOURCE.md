# Источник футбольных данных

## GOAL API — основной источник

Приложение использует [GOAL API: карточка РПЛ](https://goal-api.com/coverage/russia-premier-league-api), ID лиги `cmr77dvua00a4rx061d2jre7p`. Через серверный прокси GOAL предоставляет календарь, результаты, таблицу, эмблемы, ростеры клубов, составы матчей, запасных и формации. Для «Динамо Москва» вместо устаревшего ромба GOAL используется локальная актуальная эмблема с [официального сайта клуба](https://fcdynamo.ru/club/symbols/); «Динамо Махачкала» не изменено. Ключ `GOAL_API_KEY` остаётся в окружении сервера.

Календарь загружается через `GET /fixtures?leagueId=…&from=…&to=…&limit=100&offset=0`, таблица — через `GET /leagues/{id}/standings?season=2026`. Окно календаря — 30 дней до и после текущей даты в часовом поясе Москвы. На одной проверке 1 ноября 2026 года запрос вернул 56 матчей в окне 2 октября—1 декабря и таблицу из 16 клубов; это снимок ответа, не гарантия последующего покрытия.

Важно: ранее `GET /leagues/{id}/fixtures?season=2026` вернул записи разных сезонов, поэтому он не используется для расписания. Справка: [документация GOAL API](https://goal-api.com/documentation), [машинно-читаемая справка](https://goal-api.com/llms.txt), [тарифы](https://goal-api.com/pricing) и [условия использования](https://goal-api.com/terms).

## API-Football — только резерв портретов

Резервный источник не участвует в спортивных данных приложения. Он не поставляет клубные эмблемы, имена и номера в списках GOAL, результаты, игровые составы, запасных или формации. Сервер использует только `GET /players/squads?team={apiFootballTeamId}` и только если GOAL не прислал пригодный портрет. Идентификаторы API-Football для текущих 16 команд сопоставлены с ID GOAL в `server.mjs`.

Free-план API-Football не допускает сезон 2026/27 на сезонных endpoints. Поэтому резервная интеграция обходит сезонные endpoints и берёт текущий состав клуба. Снимок текущего состава не доказывает, что игрок входит в ростер GOAL или что его можно сопоставить с ним. Для сравнения сервер нормализует написание и транслитерацию имени; при неоднозначности фото не добавляется. API-ключ `API_FOOTBALL_API_KEY` хранится только в окружении сервера.

Проверенный squads-ответ для Dynamo Moscow содержал 28 игроков; у 26 изображение было портретом, а две разные URL содержали один и тот же общий серый силуэт. Сервер проверяет содержимое резервной картинки по SHA-256, блокирует известный общий силуэт и отбрасывает дублирующиеся картинки в одной группе совпадений. Проверка проводится только для игроков, которым нужна замена; API-Football squads-ответ кэшируется семь дней на клуб в `.cache/api-football-squads.json`, включая переживающий перезапуск дневной счётчик. Задача загружается по требованию, а внутренний лимитер ограничивает API-Football максимумом 80 API-запросов в UTC-сутки при заявленном бесплатном лимите 100/сутки. Это локальная защита для одного экземпляра сервера; несколько хостов требуют общего хранилища/лимитера.

Если GOAL уже отдал фотографию, резервный источник не вызывается для этой строки. Если нужного игрока нет в текущем squads-ответе, совпадение неуверенное, CDN не отвечает или портрет оказался общим силуэтом, приложение сохраняет инициалы. Неподтверждённые имена/ростеры из API-Football не подмешиваются в список GOAL.

## Ростеры, матчевые составы и схемы

`GET /teams/{teamId}/players` загружается при открытии вкладки состава клуба; GOAL остаётся источником имён, номеров и позиций. Кэш GOAL для ростеров действует шесть часов в процессе сервера. API-Football используется только для изображения отсутствующего GOAL-портрета.

`GET /fixtures/{fixtureId}/lineups` загружается при открытии матч-центра. GOAL остаётся источником стартового XI, запасных и формации; API-Football может добавить только проверенный портрет игрока без фото GOAL. Кэш незавершённых матчей — 10 минут, завершённых — 24 часа в процессе сервера. По снимку GOAL сообщал составы для 1 357 из 1 359 матчей РПЛ, но это не гарантирует публикацию состава к конкретному live-матчу. Одна проверенная live-игра вернула пустой состав; интерфейс показывает, что XI ещё не опубликован, а не подставляет вымышленный.

Формация отображается из поля GOAL. Визуализация располагает игроков по доступным позиционным группам и не является подтверждённой схемой координат на поле. Если GOAL не передал схему, приложение явно пишет «СХЕМА НЕ УКАЗАНА».

## События, статистика матча и сезонные вычисления

Официальная [документация GOAL API](https://goal-api.com/documentation) описывает `GET /fixtures/{fixtureId}/events` и `GET /fixtures/{fixtureId}/statistics`. Клиент запрашивает их при открытии матч-центра, а сервер допускает только fixture ID, ранее полученные из календаря РПЛ (`knownFixtures`); неизвестный ID получает 404 до обращения к upstream. События и статистика кэшируются в процессе сервера на 60 секунд для live-игры, 10 минут для ещё не начавшейся и 24 часа для завершённой. Значения нормализуются в отдельном чистом helper; неполные парные цифры отбрасываются, HTML-теги очищаются/экранируются. Пустой или ошибочный ответ показывается как недоступность, а не как нулевой результат.

Форма, домашне-гостевые показатели и H2H считаются из тех же матчей текущего сезона с распознаваемым счётом и статусом `finished`; live, будущие, неизвестные и некорректные счёты исключаются. Если GOAL сообщает, что история неполна, интерфейс помечает сезонные вычисления как частичные. H2H относится только к текущему сезону, а не к полной истории клубного противостояния. Турнирная таблица, форма и расчётные статистики имеют разные подписи происхождения, чтобы не смешивать динамические GOAL-поля со статичным демо-срезом.

Проверка сохранённого серверного ключа 11 ноября 2026 года прошла успешно: календарь сезона 2026/27 вернул 240 матчей; запросы с пагинацией до 11 декабря вернули 136 матчей и таблицу из 16 клубов. Для завершённой игры 8 ноября GOAL вернул HTTP 200 и одно событие, а endpoint статистики вернул HTTP 200 с `hasStatistics: true`. В тот момент `/fixtures/live` был пуст: live-матча РПЛ не было. Это проверка покрытия и ответов API на указанную дату, а не гарантия доступности или частоты каждого поля.

GOAL WebSocket token и handshake прошли проверку сохранённым ключом; серверу аккаунта подтверждён лимит до 25 подписок. В приложение добавлен один серверный WebSocket для известных активных матчей РПЛ, SSE-передача обновлений подключённым браузерам и повторное подключение с увеличивающейся задержкой. Счёт, минута и статус принимаются только для fixture ID, уже полученного календарём РПЛ; без валидных полей клиент ничего не подставляет. Реальное изменение счёта через WebSocket не удалось проверить: во время теста не было текущей игры. Поэтому пока подтверждены авторизация/handshake и резервный REST путь, но не end-to-end live-событие.

В ответных заголовках проверенного аккаунта был указан суточный лимит 1 000 запросов. При непрерывно работающем одном серверном процессе, клиентском REST-обновлении каждые 5 минут, двух страницах календаря (100 матчей на страницу) и 15-минутном кэше таблицы базовая оценка — около 672 REST-запросов в сутки: 576 страниц календаря и 96 запросов таблицы. Это расчёт по текущим TTL, не гарантия лимита: запросы составов, событий, статистики и портретов добавляются отдельно, а несколько серверных процессов имеют независимые кэши. После включения желательно наблюдать за фактическими quota-заголовками.

## Live-обновления и ограничения

Клиент сохраняет REST polling раз в 5 минут как резерв для расписания, результатов и таблицы. Live WebSocket используется только при наличии активных матчей, и его состояние показывается отдельно от REST-источника. При отсутствии live-игры статус остаётся `idle`; при отключении WebSocket сервер переподключается, а клиент продолжает пользоваться REST. Точность и частота upstream-feed не гарантируются; WebSocket не заменяет проверку данных в официальном источнике.

Проверенный Free API-Football текущий сезон не покрывает: сезонный endpoint ограничен сезонами 2022–2024, поэтому он оставлен только для ранее описанного резервного поиска фотографий в текущих squads-ответах и не используется как источник календаря/лайв-счёта. Бесплатные альтернативы, проверенные для этой задачи, не дают разрешённый полноценный live feed РПЛ: football-data.org Free задерживает результаты, а Sportmonks Free не включает РПЛ. Платные планы не включались; подходящей бесплатной альтернативы с подтверждённым live-покрытием РПЛ в этой проверке нет.

## Права и ограничения

Ответ API не означает, что GOAL, API-Football или владелец приложения передал права на клубную символику и фотографии игроков. GOAL отдельно предупреждает о правах третьих лиц на изображения/товарные знаки и не передаёт на них отдельную лицензию. Для изображений API-Football также нет подтверждения лицензии третьих сторон в рамках этой интеграции. До публичного или коммерческого релиза необходимо получить разрешения у правообладателей и проверить применимые условия обоих поставщиков. Скрейпинг сайтов РПЛ/клубов не используется.

## Flashscore-референс

Публичный [референс RPL Arena](https://github.com/f1dos/rpl/tree/main) использует в `rpl_flashscore_proxy.py` неофициальный внутренний Flashscore feed через `flashscore.ninja`, включая заголовок `x-fsign`. Его season-маршрут был проверен технически из sandbox и ответил HTTP 200 с 240 матчами. Это подтверждает только факт успешного ответа из той среды, не официальность API, разрешение на автоматизированный доступ, лицензию на повторное использование данных или стабильность feed. Пользователь ТЕМП разрешил оценивать такой доступ для получения большего объёма данных; это согласие не подтверждает права поставщика и не меняет его условия. Поэтому в release-candidate не копируются прокси, подписи/заголовки, фиктивно-лицензированные ответы или устаревающие JSON-снимки из референса. Отдельно проверенные [условия GOAL API](https://goal-api.com/terms) не дают разрешения на Flashscore-данные.

При отсутствии GOAL-ключа приложение честно показывает демо-режим; если GOAL REST недоступен до первой успешной загрузки, демо не маркируется как реальные данные. API-ответы и SSE не кэшируются service worker; обычные REST-кэши GOAL — процессные и теряются при перезапуске. До публичного релиза отдельно подтвердите право на использование спортивных данных и визуальных материалов.

Точный снимок оставшихся портретных пропусков по 16 клубам и проверенного матчевого состава находится в [PORTRAIT-COVERAGE.md](PORTRAIT-COVERAGE.md). Недельный кеш содержит 483 игрока из 16 squads-ответов API-Football; повторные проверки после рестарта не увеличили число его API-вызовов. Локальный лимитер не учитывает использование того же ключа другими клиентами.
