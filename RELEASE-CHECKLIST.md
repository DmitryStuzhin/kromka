## До публичного запуска

- [ ] Выбрать российский хостинг, регион дата-центра и HTTPS-домен; фактически развернуть туда приложение. Текущий Render не переносился.
- [ ] Проверить условия обработки/резервных копий/удаления у хостинга и почты; определить реальный срок хранения журналов.
- [ ] Внести `APP_PUBLIC_URL`, `LEGAL_HOSTING_PROVIDER`, `LEGAL_HOSTING_COUNTRY=RU`, `LEGAL_HOSTING_LOCATION`, `LEGAL_LOG_RETENTION_DAYS`; значения не настраивают инфраструктуру, а отражают её в документах.
- [ ] Выполнить юридическую проверку ролей двух операторов, оснований обработки, локализации, уведомлений в Роскомнадзор и наличия трансграничной передачи по фактическим потокам. Подробности — [RELEASE-OPERATIONS.md](RELEASE-OPERATIONS.md).
- [ ] Назначить ответственных за почту, сроки обращений, удаление и инциденты; включить MFA для административных доступов.
- [ ] На итоговом окружении: `npm run check`, `npm test`, `node --env-file=.env scripts/release-check.mjs` с кодом 0.
- [ ] Выбрать способ сборки Android, создать проект и package ID, реализовать самостоятельные функции приложения и собрать подписанный APK. Простую упаковку сайта в WebView не считать готовым релизом; критерии — [RUSTORE-RELEASE.md](RUSTORE-RELEASE.md).
- [ ] Проверить итоговые разрешения, SDK, резервное копирование и хранение данных APK; привести политику и очистку данных в соответствие с реальным поведением.
- [ ] Проверить пользовательские сценарии, установку/обновление APK на реальных Android-устройствах, работу TLS, кнопки Back и офлайн-состояний. Для веб-версии отдельно проверить установку PWA. Браузерная проверка не заменяет тест установленного APK.
- [ ] Выбрать издателя в RuStore, заполнить анкету и возрастную классификацию, добавить публичную политику, подписанный APK и реальные скриншоты из него. Не публиковать ключ подписи и документы издателя в репозитории.
- [ ] Провести выкатку и smoke-проверки по регламенту; убедиться, что опубликованы конечные контакты и параметры хостинга.
