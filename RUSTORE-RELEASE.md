# Пакет к выпуску КРОМКИ в RuStore

Дата подготовки: 21 ноября 2026 года. Серверная часть: https://tokenapp.ru на VPS 185.84.162.91. Android-проект создан на Capacitor 8: интерфейс и документы включены в APK, API вызывается по HTTPS. Package ID первой тестовой сборки: `ru.tokenapp.kromka`, версия 0.2.0, versionCode 1. Подписанный релизный пакет, проверка на устройстве и публикация ещё предстоят.

## Тестовая Android-сборка

`npm ci && npm run mobile:sync` готовит локальные файлы интерфейса и Android-проект. Сборка: `cd android && ./gradlew assembleDebug` (JDK 21 и Android SDK 36). Workflow `Android APK` выполняет это в GitHub Actions и сохраняет `kromka-debug-apk`. Debug APK подписывается тестовым ключом и не предназначен для публикации в магазине; ключ релизной подписи выбирается отдельно до первого выпуска.

Текущие функции оболочки: локальные файлы интерфейса и документов, запросы только к HTTPS API, сохранение последнего календаря и таблицы с датой обновления, обработка Android Back, открытие внешних HTTPS-ссылок через браузер. В manifest заявлен INTERNET, резервное копирование Android выключено. Подключены только App и Browser от Capacitor; SDK уведомлений и аналитики ещё не добавлены. Эти свойства требуют проверки на телефоне, а не только сборки.

Карточка RuStore создана: ID приложения `2063792816`. Это не ID push-проекта. В аккаунте пользователя раздел push пока не найден; документация RuStore описывает «Push-уведомления → Проекты», но наличие этого раздела для текущего аккаунта не подтверждено. Не подменять сервисный токен push ключом API публикации.

## Решение по Android-оболочке

Простая упаковка URL сайта в WebView не считается достаточной подготовкой. Правила RuStore требуют дополнительную функциональность и самостоятельный пользовательский опыт для таких приложений. Это критерий выбора оболочки и проверки результата, а не обещание прохождения модерации.

Для сохранения текущего интерфейса при выборе WebView/гибридной оболочки нужно сначала определить и реализовать дополнительную ценность: например, просмотр последних сохранённых результатов/матчей без сети с явной датой обновления, локальное избранное и встроенный экран офлайн-состояния. Сам по себе кеш CSS и шрифтов не заявлять как полноценный просмотр матчей без интернета. Нативные уведомления не подключать только ради галочки: это меняет разрешения, инфраструктуру и политику.

До реализации оболочки определить: локальные или удалённые web-ресурсы, origin хранилища, поведение кнопки Back, внешние ссылки и почта, обработка разрыва сети, обновления, безопасные настройки WebView, список разрешений и SDK. Если хранение вынесено из WebView в нативную базу, адаптировать очистку и политику — веб-кнопка не удалит эту базу автоматически.

## Проверки APK перед отправкой

- [x] Выбран и зафиксирован инструмент сборки; создан Android-проект и уникальный package ID; debug APK собран в GitHub Actions.
- [ ] Есть законченная дополнительная функциональность оболочки и понятное поведение без сети.
- [ ] Финальная сборка подписана release-сертификатом, debug-режим выключен. Резервная копия ключа и паролей хранится безопасно вне GitHub. Для обновлений сохраняется та же подпись.
- [ ] Проверены `AndroidManifest.xml`, merged manifest, все разрешения, SDK и зависимости, диагностические логи, автозапуск сетевых запросов и резервное копирование данных Android.
- [ ] Нет ненужных разрешений на геолокацию, контакты, камеру, микрофон, телефон, внешнее хранилище и идентификаторы устройства. INTERNET и другие технические разрешения, если нужны, задекларированы точно.
- [ ] Контент загружается по HTTPS, небезопасные сертификаты не принимаются, WebView debugging и неоправданные JS-мосты выключены в релизе. Внешние адреса не получают привилегии собственного интерфейса.
- [ ] Политика и условия доступны и по публичному URL из карточки, и из самого APK. Документы соответствуют реальным разрешениям/SDK; Android-упаковка не может автоматически наследовать вывод «аналитики нет» без проверки.
- [ ] Избранное очищается внутри установленного приложения; Android «Настройки → Приложения → КРОМКА → Хранилище → Очистить данные» проверено на устройстве. Удаление браузерных данных и данных APK различается.
- [ ] Проверены холодный запуск, установка/обновление поверх предыдущей версии, Android Back, переход в почту и назад, сворачивание, потеря сети, большие системные шрифты и разные размеры экранов.
- [ ] Пройдена проверка на поддерживаемых реальных Android-устройствах, в том числе без сервисов Google. Минимальную/целевую версию Android сверить с актуальными требованиями RuStore.

## Материалы магазина

- Иконка магазина: 512×512 PNG/JPG, до 3 МБ, заполненная по всей площади; должна соответствовать установленной иконке. Текущую иконку приложения сверить после сборки, не менять эмблемы клубов в рамках этой задачи.
- Подготовить несколько актуальных вертикальных скриншотов **из окончательного APK**: список матчей, детали/хронология, состав, статистика, избранное. Скриншоты браузера не выдавать за APK. Без системных панелей и обещаний отсутствующих функций.
- Состояния и тексты должны быть на русском. Форматы, размер и количество медиа перепроверить в консоли перед загрузкой.
- Отдельная отложенная задача: источники спортивных данных, прокси, эмблемы и права на материалы. Текущая подготовка документов не объявляет эти вопросы закрытыми.
